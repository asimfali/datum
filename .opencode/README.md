# .opencode — агенты и ключевые слова

Меню под задачу: агент выбирает модель и уровень усилия, команда — агента. Автор сам решает, что
запускать; здесь только перечень.

## Агенты

| агент | модель | когда |
|---|---|---|
| `architect-light` | `cliproxy/glm-5.3-flash#low` | только разговор: без правок, без делегирования |
| `architect` | `cliproxy/glm-5.3-flash#high` | обычный план, решения, брифы |
| `architect-max` | `cliproxy/glm-5.3-flash#max` | сложная задача: варианты, критерии, спорные места |
| `architect-sol` | `cliproxy/gpt-6.2-sol#high` | самая сложная задача: новый контракт, неясная геометрия |
| `worker-light` | `cliproxy/deepseek-v4.1-flash#low` | механические правки: тексты, переименования, документация |
| `worker` | `cliproxy/deepseek-v4.1-flash#high` | реализация по брифу |
| `worker-max` | `cliproxy/deepseek-v4-pro#max` | тяжёлые участки: сложная геометрия, отладка |
| `reviewer` | `cliproxy/deepseek-v4.1-flash-200k#high` | ревью diff (окно 200k) |
| `reviewer-pro` | `cliproxy/deepseek-v4-pro#high` | тяжёлое ревью, только по прямой просьбе |

`architect-sol`, `architect-max`, `architect-light`, `worker-max`, `worker-light` — тонкие варианты: их тело отсылает к
`architect.md`/`worker.md`, чтобы правила проекта жили в одном месте.

`worker*` и `reviewer*` — `mode: subagent`: в меню агентов TUI их нет, попасть в них можно командой
(`/делаем`) или делегированием.

Ревьюер — намеренно другое семейство, чем архитектор (GLM): другое мнение важнее скорости. Окна
подобраны под расход: `deepseek-v4.1-flash-200k` — 200k, чтобы сессия ревью не росла до миллиона;
`glm-5.3-flash` — 300k (у GLM ~75% расхода — cache read, и потолок окна бьёт именно туда);
`architect-sol` — 400k.

## Ключевые слова

| команда | агент | что делает |
|---|---|---|
| `/обсуждаем` | `architect-light` | обсуждение, правок нет |
| `/план` | `architect` | план и обсуждение, код не пишется |
| `/план-макс` | `architect-max` | то же для сложной задачи |
| `/план-сол` | `architect-sol` | то же для самой сложной задачи (GPT-6.2 Sol) |
| `/делаем` | `worker` | реализация в текущей сессии |
| `/делаем-лайт` | `worker-light` | механические правки |
| `/делаем-макс` | `worker-max` | тяжёлая реализация |

В команде `agent:` выбирает агента, `subagent: false` оставляет работу в текущей сессии (видно ход,
можно прервать). Разворачивает команды TUI (и `POST /api/session/{id}/command`): подставляются шаблон,
агент и модель. `opencode run "/план"` команду не разворачивает — модель получает строку `/план` как
обычный текст, поэтому в скриптах передавай текст задания и `--agent`/`--model` явно.

## Что должно быть на машине вне репозитория

Варианты `#low/#high/#max` не берутся из воздуха: их даёт `capabilities.reasoning.effort`, а
пропускает — лестница `thinking.levels` в конфиге прокси. Обе лестницы должны совпадать, иначе клиент
покажет вариант, а прокси ответит `level "..." not supported, valid levels: ...`.

Исключение — codex-модели (`gpt-6.2-sol` и родственные): у них `reasoning.effort` в глобальном конфиге
намеренно не задан, лестница `low/medium/high` приходит от codex-апстрима, а несовпадение с прокси даёт
400. Поэтому у `architect-sol` варианта `max` нет, верхний — `high`.

Лестница живёт в двух файлах, потому что у алиаса нет наследования: базовая модель — в глобальном
`~/.config/opencode/opencode.json`, алиас `deepseek-v4.1-flash-200k` — в проектном
`.opencode/opencode.json`. Меняется лестница на прокси — правятся оба.

`thinking.levels` применяется только рестартом сервиса прокси (watcher перечитывает `headers`, но не
лестницу; проверено на локальной копии прокси), клиентский конфиг — без рестарта.

Глобальный конфиг (V2-форма; ключ подставь свой, в репозиторий он не попадает):

```jsonc
"providers": {
  "cliproxy": {
    "package": "@opencode/ai/providers/openai-compatible",
    "settings": { "baseURL": "http://127.0.0.1:8317/v1", "apiKey": "<proxy key>" },
    "models": {
      "glm-5.3-flash": {
        "capabilities": {
          "reasoning": { "supported": true, "effort": ["low", "high", "max"] }
        },
        "limit": { "context": 300000, "output": 32000 }
      }
    }
  }
}
```

Внимание: варианты работают только в V2-блоке `providers` (множественное число). В V1-блоке
`provider` у модели другая форма `variants` (объект, не массив), и массив там молча выбрасывает весь
провайдер — все модели отвечают `Model unavailable`.
