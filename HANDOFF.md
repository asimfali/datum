## Задача

**Текущая — лофт-фланец (D264, ветка `feat/transition`), РЕАЛИЗАЦИЯ В ЯДРЕ, ОСТАНОВКА ДО ЗАВТРА (2026-11-14 вечером, по решению автора).** Операция `transition`: два замкнутых профиля на параллельных плоскостях → фасетное тело-лист. Контракт целиком в `ARCHITECTURE.md` D264 (финальная версия, все правки автора в ней). Ход реализации: разметка/скелет/топология — готовы и закоммичены; остался **монтаж граней тела** (следующий воркер-сеанс собирает его по брифу ниже). Затем: эталон `tests/models/transition.json` + bless, `check.sh`, развёртка `unfold` с инвариантами, отчёт автору.

**Контракт эталона (коротко, всё — по решениям автора):** плоский треугольник над каждым прямым участком A (вершина = точка B над серединой), конус-веер над каждой вершиной A (фасеты по допуску — параметр операции, хорда ≤ допуска); **гибы с радиусом правила на всех внутренних рёбрах** (28 на эталоне); **разгрузочные вырезы (секторы многоугольника) в каждой вершине разметки — снизу и сверху** (вариант b: банды обрываются торцами ⟂ осям до кромки, `p_k` срезается вырезом, верхняя кромка = хорды до линий касания); шов — настоящее ребро с `gap` (как `Rolled`), через середину первой стороны; толщина `side` как у обечайки; кромка заготовки — ломаная по фасетам.

**Топология монтажа (решено, соблюдать):** линия касания расщепляется торцевой плоскостью бенда на «фасета↔гиб» (касательно) и «фасета↔стенка подрезки»; всякое подрезанное ребро замыкается стенкой сквозь толщину (образцы: кромки стадии 0, шов обечайки, стенки фланца); продольный рез крайней банды — образующая на цилиндре, его стенка — полуплоскость через ось (плоскость); торец бенда — плоский кольцевой сектор (дуги на цилиндрах r+t/r, радиальные рёбра — со стенками подрезки); правило: у каждого ребра ровно две грани, validate после каждой группы.

**Порядок остатка (бриф воркеру):** (0) **исправить баг в `Relief.q`/`ends`, найденный при остановке**: расстояние от ребра гиба до линии касания = `radius_out·tan(sweep/2)` (≈1.27 мм при sweep≈14.5°), а не `radius_out` — верно только для 90°-гибов; с неверной формулой `q` уходил на ~106 мм от угла (z≈103), а фактическое пересечение линий касания — на ~13.6 мм (z≈13); пересчитать `q`/`ends`, проверить `sides`, расширить `verify`; (1) достроить данные `Layout`/`Relief` верха (`b_i` — торец через пересечение двух линий касания на плоском треугольнике; внутренние `p_k` — торец ⟂ оси через середину точек касания линий с хордами) + точки расщепления и `q1`/`q2` на кромках, расширить `verify`; (2) монтаж группами с validate: фасеты (подрезки) → цилиндры гибов с дуговыми торцами → стенки подрезки → боковые стенки секторов + торцевые секторы → кромки с прерываниями на вырезах → шов; (3) поднять отказ `transition()`, эталон 80×80 → R90 (t=2, радиус гиба 8, допуск 1, gap как у `Rolled` требует) + bless (только новые ключи) + `check.sh`; (4) `unfold` с инвариантами (сумма хордовых сегментов круглой кромки между вырезами = 2πR ± хорда; прямые кромки = 80; кромки шва равны; вырезы присутствуют). При исчерпании контекста — немедленное краткое состояние. Структура фасет подтверждена: треугольник ровно с 1 кромочным и 2 гибовыми рёбрами.

**Плановые задачи за переходом** (ROADMAP «Дальше», записаны сегодня): переделка построения дуги (начало → конец → радиус), многоугольник по окружности/дуге на клавише N со значком как у массива.

Штамп-компонент (ROADMAP 0.5.5, issue #248) — **этап 1–2 влит в main (PR #250, squash `6ca09c2`, 2026-11-14), формовка на паузе**: контракт формовки не сошёлся (3 открытых вопроса), концепция менялась дважды. К возврату задачу ведёт этот файл, раздел «Следующий шаг» (п.3).
