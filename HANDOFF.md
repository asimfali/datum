# HANDOFF — текущая задача

> Память между сессиями: только текущая задача. Потолок — 2k токенов. Долгие решения — `ARCHITECTURE.md` (D*), планы — `status/`.

## Задача

Библиотечная штамповка 0.5.6, первый язык на плоской стенке. План влит в PR #275, шаги в `status/stamp-component.md`. Автор открывает тестовые модели из `C:\develop\datum-test\Детали\`. Копировать туда эталоны для ручной проверки. Там же лежат исходный язык со скруглённым носиком и жалюзи.

## Состояние

- Прямой эталон `tests/models/stamp-tongue-straight.json` строит одну деталь и содержит узел `unfold`. Luna подготовила эталон и проверила его через `Session`. Terra реализовала смещение профиля и сшивку в `crates/datum-ops/src/component/`.
- D288, D292: `component.part.forming` строит язык из двух эскизов и сшивает с прямолинейной выпуклой пластиной без отверстий. `Formed` хранит предварительный рез, `unfold` и `Session::flat_of` выводят три свободные стороны без линии у корня. Операции, которые не умеют сохранять язык, явно отказывают.
- В D294 поле `round_section: true` в `component.part.forming` включает касательные гибы у корня, полки и носика. `tests/models/stamp-tongue-rounded.json` строится как отдельный эталон. Толщина, внутренний радиус и K-фактор приходят из правила листа. Окно и предварительный рез используют один размер по нейтральному слою.
- Этап штамповки с радиусами влит в `main` через PR #278.
- D295 готов в ветке `feat/edge-fillet`, PR #279. «Кромка» работает на выпуклых прямых рёбрах между параллельными плоскими торцами. F открывает инструмент, Tab переключает скругление и симметричную фаску. Носик языка и операция детали используют общий расчёт.
- Пробивка `cut` доступна с 0.5.5. Метаданные кривых и пресеты влиты в PR #274.
- D293: у отдельных окон единая память положения, размера и развёрнутости по стабильным именам. Подключены все таблицы и окно пресетов скругления. Прежнее состояние «Правил» переносится автоматически. Тесты размещения покрывают два монитора с разным DPI и отключение второго. На Windows «Правила» и «Материалы» восстановили разные положения и размеры после перезапуска.
- D296 готов: `edge_finish` принимает ровно одно из `edge`, `edges` (набор рёбер), `faces` (набор торцов) с одним размером и режимом; набор применяется за раз, дедуплицируется, непомещающийся размер отказывает атомарно. Резолвер `edge_finish_targets` общий для ядра и отрисовки ссылок. Сцена хранит угловые рёбра каждого плоского торца. Инструмент работает как эскизное филе (D240/D283): подсказка и пресеты у курсора, клик по торцу/ребру сразу создаёт операцию набора и расширяет её следующими кликами того же размера; клик по члену снимает его, последний — удаляет операцию. Окно только для правки из дерева.
- PR #280 (ветка `feat/edge-sets`, коммиты D293 + D296) открыт. Найдено и исправлено мерцание при наведении при стоящем превью: пикинг «Кромки» теперь идёт по базовым телам без превью (`edge_base`, `Scene::pick_in`). Ревью диффа: исправлены мёртвый экспорт `edge_finish_corner`, мёртвая проверка пустого набора, клик по чужой цели в окне правки, устаревший hover при уходе курсора, дубль подсказки/пресетов (`draw::size_hint`), Enter со старым размером окна, дубли 800×400 и парсера `TopoId::parse` (в datum-brep). Отложены O(V·E) разворота торца и расхождение подсветки/ядра на торце с отверстием (записано в `status/edge-fillet.md`).
