## Состояние

- **Этап 2 в ядре готов**: `Op::Component` (лист + эскиз размещений): `PartDef` (вшитое определение с валидацией), `params` (переопределения, выражения модели), `placements` (line → ось+`fit`, point → имя/координаты), тело инструмента — мини-цикл в `datum-ops` (без `datum-graph`), кэш по (определение, параметры) внутри eval.
- **Рез по `cut`**: профиль эскиза фичи роли (extrude от эскиза) пробивает стенку через `bent::punch` (D196); рез в теле, заготовке, DXF; отказ на ролях `form`/`hinge` (до подтверждения профиля лепестка).
- **Формовка по `form` (D261)**: жалюзи по линии — сечение (симметричная цепь линий/дуг ⊥ оси, в якоре), середина — протяжка, торцы — революция (дуга → тор, центр на оси → сфера), переходы R из правила листа (R > t обязателен), контур реза выводится из матрицы (роль `cut` у жалюзи не нужна), заготовка/DXF — только рез. Результат `Value::Formed` (blank с резом). Отказы: обе роли, point-формовка, рёбра, t вне диапазона, R ≤ t, зона у кромки/дырки/гиба.
- Эталон `tests/models/louver.json` (+4 хеша в `model-hashes.json`), `TESTERS.md` (0.5.5), тесты `component` (13) + property, `scripts/check.sh` — exit 0.
- Ядерные фиксы по пути (см. ARCHITECTURE D263 и сообщения коммитов): ориентация `CurveSpec` из карты (`put` с проверкой коллизий — комплементарные дуги были молчаливой перезаписью), выбор рабочей кривой в `die_of` (нормировка направления обхода), оси дуг из концов (`arc_between`), точки сечения на оси (x=0) без отдельных вершин, куски дуг ≥ π — отказ, база φ-интеграла сферы — полюс по меридианам (D263), `with_louver` по ID граней (второе размещение).

## Решения

- D256–D258 как были. D259: группы библиотеки. **D260**: компонент-блок (вшитое определение, placements, кэш). **D261**: жалюзи — формовка постоянного сечения вдоль прямой оси; торцы скруглённые; переходы строит операция вставки по правилу листа (R к стенке, R−t к второй стороне). **D262**: контракт узла `component` (PartDef, params, placements line/point). **D263**: база φ-интеграла сферы — полюс по меридианам (замена «ближайшего» из D249; хеши эталонов не изменились).
- Ревьюер по умолчанию — GLM-5.3-Flash (пул $60); DeepSeek V4 Pro — `reviewer-pro` по прямой просьбе.
- Профиль лепестка не подтверждён: `examples/stamp-leaf.json` отсутствует на этой машине; лепесток отложен до его подтверждения автором.
- Отладочный приём задачи C (переиспользовать): жёсткая проверка спеков дуг в `attach_curves` (концы на окружности, `at(u,sweep)` = v, sweep < π) + печать плоской развёртки падающей грани в `tess::face_mesh`/`torus_mesh` — находит «комплементарные» дуги и несогласованные домены за минуты.

## Окружение
- Скилл `wsl-image-paste` (`.claude/skills/wsl-image-paste/`) — вставка картинок из буфера Windows в WSL без GUI: `shotd` кладёт путь к скриншоту в буфер, opencode прикрепляет его как `[Image 1]`.
- Скиллы ядра (`.claude/skills/`): `add-op` — цепочка новой операции, с молчаливыми местами (`reads_blank`, переименование кривых, правило листа, `reedit`); `add-surface` — поверхность от `Surface` до STEP и развёртки; `geometry-debug` — репро, `inspect_model`, бисекция, детерминизм; `bless-hashes` — перепин эталонов: чистое дерево, `determinism-check`, diff после bless.
- Скилл `pr` — открытие PR: ветка от свежего `main`, `scripts/check.sh`, `HANDOFF.md`, тело по `.github/pull_request_template.md`, ревью `reviewer`, мерж через `merge-pr`. Скилла синхронизации нет намеренно: это `git pull --ff-only`, и он уже есть шагом в `merge-pr`.
- `rg` 15.2.0 (статический musl) в `~/.local/bin` — для shell-однострочников и поиска вне репозитория; агентский поиск идёт встроенными `grep`/`glob` (правила «Поиск» в `AGENTS.md`), чтобы не зависеть от машины. На Windows-копии `rg` нет.
- Провайдер моделей на этой машине — `cliproxy` (локальный CLIProxyAPI, `127.0.0.1:8317`). `model:` в `.opencode/agent/` должен совпадать с ID провайдера на машине, иначе агент не запускается: `Model unavailable`. У `glm-5.3-flash` в глобальном конфиге задан `limit: {context: 1000000, output: 32000}` (иначе OpenCode считает от 200K).
- Связь с домашней машиной — через комментарии в GitHub issue (чат сессий не общий).
- Несколько проектов и агентов: набор `~/develop/agent-kit` (отдельный репозиторий). Глобальные правила `~/.config/opencode/AGENTS.md` (симлинк), граница владения — плагин `~/.config/opencode/plugins/project-guard` (симлинк, `plugins` в глобальном `opencode.json`), шина между проектами — `ab` (`~/.local/bin/ab`, ящики в `~/agent-bus`). Зарегистрированы `datum` и `mc`. Свой проект определяется по реестру шины; чужой код читается, запись в чужой проект отклоняется. На работе — клон репозитория + `./install.sh <пути>`, в `permissions` заменить `~/develop/*` на рабочий корень и `opencode service restart`.
