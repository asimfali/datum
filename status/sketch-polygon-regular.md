# Многоугольник: регулярность группой и перередактируемое число сторон (PR #255)

Решения автора (2026-11-17): перетаскивание — как в Inventor; проще — без
угловых связей, только равенство сторон; число сторон — через группу и
перестройку. Угловые связи у окружности НЕ ставить (решатель может счесть их
избыточными; свёртка в звезду возможна только при протаскивании вершины
сквозь соседнюю — принято сознательно).

## П.1 — связи регулярности в `plan()` (`crates/datum-view/src/polygon.rs`)

- Окружность (замкнутый): `n−1` связей `Equal` между соседними сторонами
  (`{"type": "equal", "lines": [l_k, l_{k+1}]}`). DOF остаётся 1 (вращение),
  драг вершины вращает многоугольник. Новых построительных линий НЕ добавлять.
- Дуга (открытая цепь): те же `n−1` `Equal` + `Coincident` первой вершины с
  точкой `from` дуги и последней с `to` (`arcs[a] = {"center","from","to"}`).
  Цепь жёсткая (0 DOF), перетаскивание ничего не делает; при правке дуги
  равные шаги восстанавливаются сами.

## П.2 — владение и перередактирование числа сторон

- Многоугольник = группа эскиза: `groups["polygonN"] = [точки..., линии...,
  имя кривой]` (модель групп — `datum-sketch`, `sketch.groups`; так же массив
  держит ячейку — `pattern.rs:436`). Имя группы стабильно: при перестройке
  перезаписывается, не удаляется.
- Узнавание «это многоугольник»: группа, у которой ровно один участник —
  кривая (`circles`/`arcs`), помеченная `construction`, остальные — точки с
  `on`-связями на неё и линии между ними; число сторон = длина набора линий.
  (Проверить на коллизии с ячейками массивов/путями; если состав не
  различается надёжно — первый вариант, имя группы с префиксом.)
- Бейдж группы уже есть (`sketch.rs:1553–1562`, `Pick::Group`); клик по бейджу
  многоугольника открывает форму с числом (прецедент — форма массива,
  `app.rs:8519`). Клик по бейджу обычной группы — прежнее поведение.
- Смена числа = пересборка тем же кодом, что создание: удалить старые
  элементы группы и все связи, ссылающиеся на её точки, поставить новые с
  тем же числом... с новым числом, перезаписать группу тем же именем.
  Механику удаления в `edit_sketch`-патче работник выясняет по коду; если
  удаления ключей нет — спросить архитектора, не изобретать.
- При создании: отказ, если на кривой уже есть многоугольник (поиск группы
  по составу — прецедент `sketch.rs:130`).

## Тесты (минимум)

1. Окружность: после драга вершины многоугольник регулярный (стороны равны),
   1 DOF.
2. Дуга: цепь жёсткая — солвер не даёт двигать вершины (dof=0), шаги равны.
3. Правка дуги: шаги остались равными (восстановились связями).
4. Reedit числа 6→4→8: элементы и группа перезаписаны, старых не осталось.
5. Отказ дубля на кривой.
6. Регресс: прежние тесты `polygon.rs` зелёные (обновить те, что про связи).
